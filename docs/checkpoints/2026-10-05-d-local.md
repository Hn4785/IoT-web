  dump, copy, creation, restore and migration validation. Failed `createdb`, including
  a check/create race, cannot proceed to `pg_restore` on an existing target. Invalid
  lookup/count responses fail closed; unique temporary dump names avoid collisions.
  Cleanup warnings cannot replace the primary error, even with warnings set to stop.
- Fourteen controlled PowerShell tests cover those failure/success paths. Nine
  behavioral failures were reproduced before the repair. Windows execution-policy
  setup failure was not counted as behavioral red evidence. This helper suite and
  the Docker restore integration case run on Windows, not Linux CI.
- Existing Super Admin recovery regressions verify password replacement, active
  holder-session revocation, preserved previous revocation reason/time, unaffected
  unrelated user/session and exactly one sanitized audit event. No login policy change.
- A fresh GUID-named restore of guarded local `iot_test` compares users/sessions,
  hierarchy/memberships, source ciphertext/grants/key scopes, readings/snapshots,
  coverage/checkpoints, rules/alerts/events, notifications and audit. The restored
  application returns readiness, authorized stored moisture 42 with original sample/
  fetch timestamps during a controlled provider failure, the owner's notification
  and denied outsider scope. Decryption uses the separately supplied fixture key;
  no real provider credential or data is used in these tests.
- Owner-approved dependency patch pins Nest runtime/testing 12.0.3 and Fastify
  5.12.5, with constrained fast-uri, ip-address and brace-expansion transitive ranges.
  Node, pnpm, Prisma, release-age and allowed-build policies remain unchanged.
  Codex reviewed the bounded three-file worker diff and independently verified it.
  Relevant primary patch notices: [Nest advisory](https://github.com/nestjs/nest/security/advisories/GHSA-9c5c-9qcx-q35q)
  and [Fastify advisory](https://github.com/fastify/fastify/security/advisories/GHSA-4mh8-r7rc-xpvc).
