# Checkpoint A1 — Persistence and Administrator Provisioning

Date: 2026-09-02

## Accepted scope

- PostgreSQL 17 runs through Docker Compose and persists under `E:\IoT-data\postgres`.
- The reproducible Prisma migration creates the identity, authority, session, farm/station scope,
  API-key and security-audit foundations, including the `citext` extension.
- An interactive, one-time command bootstraps the initial active Super Admin without accepting a
  password in arguments, environment variables, migrations or logs.
- Protected administrator APIs create, list, read, update and reset users across the `ADMIN`,
  `FARMER` and `CLIENT_DEVELOPER` roles.
- Normal Admins cannot create/mutate Admins or mutate themselves. Only the current singleton Super
  Admin can perform Admin-role changes. The authority holder cannot be disabled or demoted before a
  transfer.
- Role/status changes revoke sessions and API keys and remove incompatible grants in the same
  serializable transaction.
- Public responses use safe user DTOs, one-time credential responses use `Cache-Control: no-store`,
  and tracked files contain none of the local database/JWT/pepper values.

## Contract boundary

The OpenAPI document includes `/api/v1/admin/users` and its user/reset routes. There is deliberately
no `/api/v1/auth/login` at A1. Integration tests sign a short-lived access JWT directly and the guard
reloads active role and Super Admin authority from PostgreSQL; browser login/session issuance begins
at IA-4 / Checkpoint A2.

## Evidence

- A fresh disposable `iot_a1_verify` database applied the migration successfully, contained the

- `15` test files and `79` tests passed on Node `24.19.0`.
- Lint, TypeScript typecheck, formatting, production build and dependency audit passed.
- Docker reported PostgreSQL healthy on `127.0.0.1:5432`.
